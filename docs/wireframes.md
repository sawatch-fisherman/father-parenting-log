# TotoOps MVP 画面詳細レイアウト（ワイヤーフレーム）

> 本ドキュメントは、[screens.md](screens.md) で確定した画面一覧（S1〜S13）・ルーティング・Controller構成を前提に、**各画面内のコントロール配置（ボタン・入力欄・タブなど）のみ**を決めるものです。色・余白・フォント・アイコン意匠などの視覚デザインは対象外です。
>
> 4×2アイコングリッド（S3・S9）／期間タブ＋集計（S12）／日付グループのタイムライン（S13）は、参考として類似アプリ（Studyplus）のスクリーンショットを参照して構成しています（参考画像はローカル専用ファイルのためリポジトリには含めていません）。

## 記法凡例

| 記法 | 意味 |
|---|---|
| `[ボタン]` | ボタン |
| `(入力欄)` | テキスト入力 |
| `<セレクト ▾>` | ドロップダウン／セレクト |
| `《タブA｜タブB》` | タブ切り替え |
| `┌─┐│└─┘` | カード／グリッドの枠線 |
| `…` | ケバブメニュー（その他操作） |
| `>` | タップで詳細・次画面へ遷移することを示す行末記号 |

## S9 ピン留め設定画面

```text
┌─────────────────────────────┐
│ [← 戻る]  ピン留め設定        │
├─────────────────────────────┤
│  現在の8枠（タップで入れ替え） │
│ ┌──────┬──────┬──────┬──────┐│
│ │①おむつ│②ミルク│③お風呂│④寝か││
│ │交換  │      │      │つけ  ││
│ ├──────┼──────┼──────┼──────┤│
│ │⑤夜泣き│⑥着替え│⑦歯磨き│⑧送迎││
│ │対応  │      │      │      ││
│ └──────┴──────┴──────┴──────┘│
│                             │
│          [ 保存する ]        │
└─────────────────────────────┘
```

- 8枠のうち1つをタップすると、下記の入れ替えモーダルが開く。`[⇄]`のような小さい操作アイコンは置かない（スロット全体を大きいタップ領域にすることで誤タップを防ぐ。S3のグリッド設計と同じ考え方）。
- **ピン留めは最大8個で、8個未満（空きスロットあり）のまま保存できる**。空きスロットはS3と同じ`＋`表現で描画し、タップすると同じ入れ替えモーダルから育児行動を1件選んで埋められる。逆に、埋まっているスロットを空にする操作はこの画面には置かない（誤操作でグリッドが空になるのを避けるため。空きが生まれるのはPhase 2でカスタム育児行動を削除したときのみ。[decisions.md](decisions.md) §1.3）。
- 画面下部に「候補一覧」を常設しない（Phase 2でカスタム育児行動が増えると縦に伸びて保存ボタンが遠くなるため）。候補はモーダル側でスクロール表示する。
- 保存でS7へ戻る。

## S10 実施日時指定画面

```text
┌─────────────────────────────┐
│ [← 戻る]   おむつ交換         │
├─────────────────────────────┤
│ 実施日                       │
│ ( 2026-07-15              ) │
│  記録できるのは7日前まで      │
│                             │
│ 実施時刻                     │
│ ( 21:30                   ) │
│                             │
│ メモ（任意）                 │
│ (                         ) │
│                             │
│          [ 保存する ]        │
└─────────────────────────────┘
```

- ヘッダーには選択済みの育児行動名を表示のみ。S3の長押し、またはS4の項目タップから遷移。
- 保存後、称号条件達成ならS5へ、未達成ならS3へ遷移。
- **実施日ピッカーの選択可能範囲は「7日前 〜 今日」に制限**する（[decisions.md](decisions.md) §1.3「育児ログの遡り操作は直近7日に制限する」）。範囲外の日付はピッカー上で選択不可にし、入力欄の下に補助テキストで理由を添える。文面は責めるトーンにせず、「記録した時点の状況を正しく残すため」という趣旨にとどめる。
- 実施時刻は分精度。サーバー側では `occurred_at`（実施日＋実施時刻）を「7日前の00:00 〜 現在＋5分」で検証する。
- **実施日に「今日」を選んだ場合のみ、実施時刻の選択上限を「現在時刻＋5分」に制限する**（過去日を選んだ場合は `00:00`〜`23:59` を自由に選べる）。実施日ピッカーだけを制限してもS10単独では未来時刻を入力できてしまい、サーバー側の上限（現在＋5分）と食い違うため。範囲外を入力した場合はサーバー側でも同じ条件で弾き、UI・サーバーの二重で担保する。

```text
│  17:00 離乳食・食事補助   … │
│                             │
│ 2026年7月14日                │
│  23:10 夜泣き対応        … │
│  ───────────────────────── │
│  ...                        │
│                             │
│ 2026年7月5日                 │
│  08:00 朝の身支度         ・ │← 非活性
├─────────────────────────────┤
│  記録 │ 履歴 │ 集計 │ 設定    │
└─────────────────────────────┘
```

- 新しい順、日付ごとにグループ化。各行の「…」タップでS11へ遷移。
- **`memo` がある行のみ、育児行動名の下に2行目としてメモを表示する**（空の場合は行自体を出さない）。長文は末尾を省略表示し、全文はS11で確認・編集できる。メモを表示するのはこの画面のみで、S12（集計）には出さない（[decisions.md](decisions.md) §1.3、[data-model.md](data-model.md) ④）。
- **`occurred_at` が「7日前の00:00」より前の行は「…」を非活性**にし、S11へ遷移できないようにする（編集・削除とも不可。判定の境界はサーバー側の遡り制限と同一。[decisions.md](decisions.md) §1.3）。タップされた場合は「7日を過ぎた記録は変更できません」という趣旨のトーストを出し、責める文面にしない。7日以内の行と見分けがつくよう、非活性の「…」はグレーアウトする。

### 削除確認モーダル

```text
┌─────────────────────────────┐
│ ░░░░░░░░░░░░░░░░░░░░░░░░░░░ │
│  ┌───────────────────────┐  │
│  │ ⚠ 削除の確認            │  │
│  │                       │  │
│  │「ベビーマッサージ」を    │  │
│  │ 削除しますか？          │  │
│  │                       │  │
│  │ この育児行動で記録した   │  │
│  │ 過去の育児ログもすべて   │  │
│  │ 削除されます。          │  │
│  │                       │  │
│  │ [キャンセル] [ 削除する ]│  │
│  └───────────────────────┘  │
└─────────────────────────────┘
```

- `[削除]`タップ時に表示。削除は物理削除で、紐づく`care_logs`も`ON DELETE CASCADE`で道連れに削除されるため、実行前に必ずこの警告を経由する（decisions.md §1.3）。「キャンセル」で何もせず一覧に戻る。
- 削除対象がS3にピン留めされている場合は`user_slot_configs`の行も`ON DELETE CASCADE`で消え、**S3のグリッドに空きスロットが1つできる**（[data-model.md](data-model.md) ⑤）。ピン留め中でも削除自体はブロックしないが、モーダルの警告文に「記録画面のピン留めからも外れます」の一文を足し、削除後にS9で埋め直せることを添える。
