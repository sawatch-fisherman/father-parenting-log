# TotoOps 機能一覧

> 本ドキュメントは Laravel 実装前の企画整理段階の資料です。
> 機能の案出しと整理が目的であり、確定仕様ではありません。判断が必要な点は [decisions.md](decisions.md) の「未決事項」に整理しています。

実装フェーズは以下の4段階に分けます。

- **MVP**：最初に作る最小機能。父親の育児ログ・称号・X投稿文・自分の集計に絞る。
- **Phase 2**：他の父親の育児「傾向」を見る集計機能。
- **Phase 3**：PWA 化・通知など、使い勝手の向上。
- **将来案**：AI 要約や NativePHP など、Web 版が形になってから検討。

## フェーズ別サマリ

> 方針：**シンプルな機能から実装する**。外部サービス連携（LINE）や広告は後回し。
> ただし下記「基盤」は機能ではなく土台であり、**後付けは高コスト**なので MVP の設計段階で最初から組み込む。

### 基盤（MVP の DB／設計段階で最初から入れる）

- ID／主キーの **UUID 化（UUIDv7 / ULID 推奨）**
- **ログテーブルとマスタ／ユーザーテーブルの分離**
- **二重送信防止（冪等性）** … ボタン同時押しでも2重登録させない

詳細は [decisions.md](decisions.md) の「設計原則（アーキテクチャ）」を参照。

### MVP（最初に作る）

1. ユーザー登録・ログイン
2. プロフィール登録（ニックネーム：必須／年代・子どもの年齢帯：ともに任意）
3. 育児イベント種別管理
4. 育児イベント登録
5. ダッシュボード集計（今日・今週・今月）
6. 累計実績表示
7. 称号獲得（累計回数方式）
8. X投稿文生成・コピー
9. 設定画面（ハブ：プロフィール編集＋各機能への入口）

### Phase 2（自分の詳細分析／他の父親の傾向を見る／育児の節目）

- **日別育児タイムラインチャート**（横軸：時間帯・縦軸：回数。`occurred_at` の時刻を活用）
- 全体タスク傾向（**タスク種別ランキング表示**＋設定からの導線）
- 年代別タスク傾向
- 子ども年齢帯別傾向
- 卒業＆エンドロール

> 傾向集計で並べるのは“育児タスクの種類”のみ。個人ランキング・県別ランキング・母親との比較は行いません（[concept.md](concept.md) §3.3）。

### Phase 3（使い勝手の向上・継続支援）

- PWA 化
- 称号獲得通知
- 放置リマインド通知（母親バージョン）
- 頑張りすぎアラート（父親バージョン）

### 将来案

- LINE 共有（外部連携・後回し）
- 広告（設定画面のみ）
- AI 要約（孫ニュース）
- NativePHP モバイル版（API クライアントとして）

### 育児イベント種別一覧（基本8個の選定候補プール）

> **選定方針（重要）**
>
> - 下の表は **候補プール** です。**項目はすべて暫定** であり、確定ではありません。HP は不採用（廃案。[decisions.md](decisions.md) §1.6）。
> - 対象は **「父親が意思を持って行動するイベント」のみ**。子供の状態・行動が引き金になるイベントは除外（詳細は [decisions.md](decisions.md) 設計原則）。
> - **UIアーキテクチャ確定**：常時表示は **4列×2段の8アイコン固定**。中身はユーザーが自由にピン留めでき、それ以外は「その他」ボタン→別画面/モーダルからアクセスする（[decisions.md](decisions.md) §1.3）。
> - 登録時は共通のおすすめ8個で自動初期化。**具体的にどの8個にするか**は **実際に育児をして必要と感じたもの** から（机上では確定しない → [decisions.md](decisions.md) 未決#11）。ユーザーは登録後いつでも自由に入れ替え可能。

| イベント | グループ案 | メモ |
| --- | --- | --- |
| おむつ交換 | 日常ケア | 頻度が高い。回数加算が効く |
| 着替え | 日常ケア | 嫌がると負荷増 |
| 歯磨き | 日常ケア | 嫌がりやすい |
| 鼻水ケア・鼻吸い | 日常ケア | 嫌がって暴れることあり |
| 爪切り | 日常ケア | 動くと難易度高 |
| 本の読み聞かせ | 日常ケア | 時間・集中力が必要。継続習慣になりやすい |
| ミルク・授乳補助 | 食事系 | 夜間は別途対応 |
| 遊び相手（室内） | 日常ケア | 短時間でも継続は地味に消耗 |
| お風呂 | 日常ケア | 沐浴期（新生児）を含む |
| 送迎（保育園・習い事等） | 外出・移動 | 時間拘束が大きい。朝の時間圧・帰り渋りなど変動 |
| 離乳食・食事補助 | 食事系 | 散らかし対応込み |
| トイレ補助・トイトレ | 日常ケア | 失敗対応で変動 |
| 散歩・公園遊び | 外出・移動 | 見守り＋安全確保 |
| 寝かしつけ | 対応・耐久 | 時間が読めない |
| 外出中の抱っこ | 対応・耐久 | 物理負荷が大きい |
| 発熱・看病・通院 | 対応・耐久 | 精神的負荷も大きい。待ち時間＋ぐずり対応込み（通院を含む） |
| 夜泣き対応 | 対応・耐久 | 睡眠不足で翌日にも影響 |

> 統合済み：沐浴 → お風呂／病院付き添い・通院 → 発熱・看病（「発熱・看病・通院」）／保育園 送り・迎え → 送迎。
> 除外：イヤイヤ対応・危険回避（子供主体）／チャイルドシート乗降（法的義務に近い）／買い物同伴（対象年齢では外出の一形態）。いずれも設計原則「父親主体のみ」および「除外基準（追補）」に基づく（[decisions.md](decisions.md) §1.3）。
> グループ案（日常ケア／食事系／外出・移動／対応・耐久）は候補の性質を把握するための参考情報。常時8アイコンはユーザーが自由にピン留めする方式になったため、グループ分け軸そのものはUI設計上は不要（[decisions.md](decisions.md) §1.3・未決#11）。

## 放置リマインド／アラート 通知メッセージ案（10パターン）

> トーン方針：**叱責ではなく、ユーモアと寄り添い・問いかけ**。
> 思想は「母親と比較しない」のまま。狙いは **「夫婦で協力した子育て」** と、孤立しがちな母親を減らすこと（[concept.md](concept.md) §3.4）。
> いずれも暫定文案。表示はランダム想定。トーンの ON/OFF・選択は通知設定で切り替え可能にすることも検討。

### 母親バージョン（放置リマインド：しばらく記録のない父へ／妻を孤立させないか）

1. しばらくログインがないようです。奥さん、今ごろワンオペで二刀流していませんか？⚔️ そっと様子を見にいきましょう。
2. 育児、ちょっとお休み中ですか？☕ あなたが一息ついている間、奥さんも一息つけていますか？
3. 子どもの成長は早いです🌱 そして奥さんの「ひとり育児」の経験値も、知らぬ間に上がっているかも？
4. 最後の育児ログから少し経ちました。今日のおむつ、ぜんぶ奥さん任せになっていませんか？🍼
5. 育児は2人プレイ推奨のゲームです👫 どこかでソロ討伐になっていないか、のぞいてみませんか？

### 父親バージョン（頑張りすぎアラート：ログが多い父へ／抱え込み注意・夫婦で分担）

1. 毎日お疲れさまです🔥 ……ところで、あなたが倒れたら誰が育児を引き継ぎますか？たまには奥さんにパスを。
2. 育児ログ絶好調ですね！でも、ぜんぶ一人で背負っていませんか？夫婦はパーティ編成OKです👫
3. すごい記録です🏅 でも本当に強いパパは、HPを使い切る人ではなく、長く続けられる人かもしれません。
4. 今日もたっぷり育児、ありがとうございます。最後に奥さんと「育児どう分ける？」の話、できていますか？☺️
5. あなたのHP、そろそろ赤ゾーンでは？🔋 休むのも立派な育児。奥さんに「ヘルプ」を出してみましょう。
